# TouchXbox 0.5.6

在 Android / 鸿蒙 Android 兼容层上，用屏幕按键和本机传感器生成**本机系统虚拟手柄与键盘输入**，支持 Xbox、NS Pro、PS / DualShock 4、FPV USB HID 遥控器。

输入路径：悬浮控件 / 本机 IMU → 应用打包所选协议报告 → Shizuku Binder → shell / root UserService → `/dev/uhid` → Android `InputDevice` / `KeyEvent` / `MotionEvent` / 输入设备传感器。测试页的按键、轴和系统体感只显示系统回传；另分区显示本机采集和后端确认写入的协议报告，两者不计入系统体感。原有电脑 ADB 激活方式仍可在设置中选择。

## 安装与启动

在 [GitHub Releases](https://github.com/Zhgma/TouchXbox/releases/latest) 下载最新 APK。安装 0.5.6 或更新版本后，可在「齿轮 → 关于 → 检查更新」下载并安装后续版本；更新保留模板和设置。首次更新安装可能需要系统的“允许此来源安装应用”权限。发布流程与更新源迁移说明见 [OTA.md](OTA.md)，当前验证范围见 [OTA_VALIDATION.md](OTA_VALIDATION.md)。

### 手机内授权（默认）

1. 安装最新 APK，并从 [Shizuku 官网](https://shizuku.rikka.app/download/) 安装 Shizuku 13 或更新版。
2. 按 [Shizuku 启动指南](https://shizuku.rikka.app/guide/setup/) 在本机通过无线调试配对并启动；已有 Root 的设备也可直接启动。
3. 打开 TouchXbox → 齿轮 →「手机内授权」，授予 TouchXbox 使用 Shizuku 的权限，并允许悬浮窗权限。
4. 新建并保存模板，点击模板启动。授权完成后会自动继续先前请求的启动操作。

**免电脑启动的条件是系统提供无线调试配对入口，或设备已有 Root。** Android 版本号或系统报告支持 Wi-Fi ADB，不代表固件一定提供配对页面。2026-10-07 检查的华为 HBN-AL00 手机和 DBR-W10 / 鸿蒙 4.2 平板均未找到该入口；平板上的 Shizuku 实测使用现有 USB 调试连接启动。因此，接入 Shizuku 已实现，但这两台设备尚不能据此宣称已实现全程免电脑启动。Shizuku 不会绕过系统权限；设备重启后通常需要重新启动它。

### 电脑 USB / ADB 激活（兼容方式）

**已安装 APK，只需要独立授权文件：** 双击 `TouchXbox-authorize.cmd`。这个 CMD 内嵌全部授权逻辑，可单独复制到任意目录，不需要旁边放 APK、PS1 或 Shizuku。它优先使用已有 ADB；找不到时从 Google 官方仓库下载并校验，缓存到 `%LOCALAPPDATA%\TouchXbox\adb-cache`（首次下载需要联网）。设备必须已安装本应用，并在设备上允许此电脑的 USB 调试。多台设备时按序号选择。脚本会重启应用、切换到 ADB 方式、激活输入服务并尝试允许悬浮窗，保留已保存模板；运行前请保存编辑中的模板。成功提示前会实际完成桥接身份验证与 `/dev/uhid` 访问检测。设备重启或输入服务退出后需要重跑。

1. 打开设备 USB 调试，连接电脑并允许授权。
2. 双击 `activate.cmd`，安装 APK 并激活桥接。也可在 PowerShell 中运行：

   ```powershell
   .\activate.ps1 -Adb 'D:\platform-tools\adb.exe'
   ```

   多台设备时加 `-Serial '设备序列号'`；已安装可加 `-SkipInstall`。脚本自动查找 PATH、Android SDK 或 `D:\platform-tools` 下的 ADB。

3. 点击首页齿轮，在设置中允许悬浮窗权限；点击「＋」新建模板并保存。
4. 直接点击模板卡片启动。需要查看实际输入时，在齿轮设置中打开「系统输入测试」。
5. 激活后通信留在设备内部，可断开 USB；重启设备或桥接退出后需再次运行激活脚本。

## 首页与模板管理

首次安装时首页为空，不自动添加任何遥控器模板。通过右上角「＋」新建或导入；退出未保存的编辑也不会添加模板。升级会保留已有模板，并继续迁移确实存在的旧版布局。

成功启动并被系统识别为对应手柄后，桌面图标和名称切换为 **TouchXbox / TouchNS / TouchPS / TouchFPV**，使用 Xbox 绿、NS 红、PS 蓝和 FPV 遥控器四种图案。同一时间仅启用一个桌面入口；停止手柄和重开应用保留上次成功启动的协议，编辑或保存模板不触发切换。首次安装尚未启动协议时使用 TouchXbox。首页标题、关于名称和运行通知同步更新。Android 设置中的安装包名称仍为 TouchXbox。

在「齿轮 → 外观 → 图标和应用名称」可选择自动跟随，也可固定为 Xbox 手柄、NS、PS、FPV 或**原始 TouchXbox 图标**。图标和名称按对应组合切换；固定选择不会改变模板或输入协议，之后启动其他协议也保持此选择。重新选择自动时，恢复为最后成功启动的协议外观。选择会跨重启保留。

首页只展示已保存模板的预览卡片；左上齿轮展开设置，右上「＋」添加模板。界面结构参考 [Moonlight Android 首页](https://github.com/moonlight-stream/moonlight-android/blob/master/app/src/main/res/layout/activity_pc_view.xml) 和 [网格卡片](https://github.com/moonlight-stream/moonlight-android/blob/master/app/src/main/res/layout/pc_grid_item.xml)，使用本项目自己的代码和绘图。

- **点击卡片**：选择该模板并直接启动悬浮手柄。
- **长按卡片**：选择编辑、删除或复制配置；删除有确认提示。
- **复制配置**：把 `TXPAD1:…` 字符串写入剪贴板。点击「＋」→「粘贴配置」→「导入配置」，会新建独立模板；重名时自动添加编号，不覆盖原模板。
- **「＋」→「新建模板」**：打开默认布局的编辑页，保存后出现在首页。
- **齿轮设置**：系统输入测试、传感器检测、停止手柄、图标和应用名称、连接方式、Shizuku 授权、悬浮窗权限、输入服务检测及应用信息。
- 删除全部模板后保留空白库，点击「＋」重新创建；不会重新生成已删除的模板。

配置字符串包含名称、手柄协议、键盘映射、可见控件、普通/高亮名称与高亮选项、仅横屏启用选项、滑出保持选项、两种屏幕方向的肩键位置联动和位置尺寸、收起区域、组件样式、字母互换和透明度；不包含激活密钥或权限。采用带版本前缀的 gzip + Base64URL 编码，并检查内容大小、版本和基本结构。导入后仍需在目标设备完成 Shizuku 授权或 ADB 激活，以及悬浮窗授权。

## 布局编辑

- 在首页长按模板，点击「编辑」；新建模板从默认布局开始。
- 点选画布中的组件，在右侧属性区选择样式、调整大小。**顶部没有 L/R 样式按钮**。
- 拖动控件改变位置；点选蓝色「收起区域」可拖动并调整宽高。收起区域不能覆盖按键，保存时会检查。
- 点击顶部「预览」，进入当前所编辑方向的全屏预览，可按实际尺寸拖动控件和收起区域。工具条左侧可拖动避让；点击「返回编辑」或系统返回，只把改动带回草稿，仍需点击「保存」才会写入模板。预览不会发送手柄输入，不需要先激活输入服务。
- 缩略画布、全屏预览和悬浮层统一使用整屏坐标；不再从画布扣除状态栏、导航栏或刘海边距。编辑和预览隐藏系统栏，可从屏幕边缘滑出系统栏。HBN-AL00 已实测修复原来顶部/左侧各 139 px 的空白和偏移。
- 位置保存为画布宽高中的相对坐标；控件宽高保存为相对画布短边的比例，换设备后等比缩放，圆形/八边形保持形状。四肩键宽度联动、两对肩键高度及统一键盘尺寸都参与缩放；收起区域按画布宽高分别适配。超出边缘的控件会移回屏内，原始相对坐标不会因此被改写。
- 配置格式更新为 version 7（字符串前缀仍为 `TXPAD1:`），复制和导入会保留横竖屏各自的尺寸比例。接收设备需使用 0.5.3 或更新版。旧模板第一次在新版打开时，以当前设备画布捕获原有尺寸，不修改原来的位置、大小滑块或名称；此后复制到其他设备便使用保存的比例。
- 点选普通按键、键盘键、方向键、ABXY 组合或扳机，可设置「滑出后保持按下」。肩键（LT/LB/RT/RB）默认开启，其余适用组件默认关闭；旧模板沿用此默认值。开启后，按住拖出仍保持按下或最后的扳机/方向值，抬手释放；收起、取消触摸和停止同样释放。ABXY 多指逐指保留最后触区，最后一个手指释放后才松开该键。该选项不改变点按高亮名称或 FPV 辅助通道的切档逻辑。
- 点选任一肩键，在「四肩键位置联动」中选择「关闭（独立移动）」「左右对称 · 上下排列」或「左右对称 · 并列排列」。上下排列时 LT/RT 在上；并列时扳机在外侧、肩按钮在内侧，左右镜像。拖动任一肩键会同步移动四键；关闭联动保留当前位置。横竖屏各保存自己的选择和相对锚点，换设备后仍等比缩放、保持对称与间距。
- 顶部可填写模板名称，「保存」更新当前模板，「另存为」创建独立命名模板。支持 1–40 个字符，不会覆盖其他同名模板。
- 横竖屏位置与尺寸分别保存；组件样式、A/B 与 X/Y 互换和不透明度在同一模板中共用。编辑的是草稿，未保存离开会提示。
- 肩键默认为左右各一列：LT 在 LB 上方，RT 在 RB 上方；VIEW、XBOX、MENU 默认在屏幕底部居中排列。已有模板保留自定义位置，点选肩键或底部功能键后，可分别「恢复肩键上下排布」「恢复三键底部排布」，仅重设当前方向中该组控件的位置和缩放。
- 0.1 的位置和不透明度会导入首次默认模板；0.2/0.3/0.4 模板保留名称、位置和样式。旧肩键缩放迁入联动尺寸：以 LT 缩放为共用宽度及 LT/RT 高度，以 LB 缩放为 LB/RB 高度。

附带模板 [NS 跟随八边形](templates/NS-follow-octagons.txt)：复制文件内整串配置，在首页「＋」粘贴导入。左右跟随、双八边形、肩键位于左右 20%/80%；底部原三键在上、F4/F5/F11 在下，六键等大。使用 0.5.2 或更新版。

## 组件样式

| 组件 | 样式与操作 |
| --- | --- |
| L / R 摇杆 | 各自选择固定位置或对应半屏浮动。浮动模式下，在该侧没有其他控件且不在收起区域的位置落指，落点即中心，拖动拨杆。FPV 双摇杆使用正方形操作范围。 |
| 摇杆按下 | 两种样式都支持原地长按 0.5 秒触发 L3/R3，随后可继续拖动，松手或取消释放。普通拖动不会到时自动触发长按。 |
| LT / RT | 各自选择向下滑动的模拟量样式，或点击样式。点击时按下即满值、松手归零，滑出行为由「滑出后保持按下」控制。滑动样式位置越靠下力度越大。 |
| LB/RB 与 LT/RT | 四键均收窄，LB/RB 保持原来的高度，仅 LT/RT 加高。默认布局单位为 LB/RB 64×55、LT/RT 64×86，按屏幕比例缩放；名称居中。滑动扳机底部有向下箭头，点击样式没有箭头。 |
| 肩键尺寸 | 点选 LT/LB/RT/RB 中任一键，使用「宽度（四键联动）」同时调整四键宽度；使用单独的高度滑块调整 LT/RT 或 LB/RB 这一对的高度。两组高度互不影响。位置另有可选联动，不改变尺寸联动规则。 |
| ABXY | 四个独立圆键，或「八边形组合」（新模板默认）。组合显示八边形边界和四个字母，不画内部对角线、不填充背景。按下时字母变亮、略微放大。内部四触区可多指组合、跨区滑动，交点有很小的中立区；八边形四角外侧不触发按键。编辑时选中组件会显示辅助选框。 |
| A/B、X/Y 互换 | 点选任一 ABXY 组件，在右侧分别勾选「互换 A / B」「互换 X / Y」。默认上 Y、左 X、右 B、下 A；互换同时作用于显示字母、颜色和实际手柄输入，两种 ABXY 样式通用，并随模板保存。 |
| 方向键 | 圆形、十字键、八边形。八边形仅显示上下左右箭头，所有样式仍支持八方向输入。 |

控件的系统触摸窗口为外接矩形，ABXY 组合会进一步排除八边形外侧的四角。左右浮动窗口位于按键和收起区域之下，新触摸优先交给按键或收起区域；已开始的摇杆手势可继续拖动。固定模式下控件窗口之外的空白区域可供下层应用使用。

## 协议、体感与 FPV

在编辑页的协议菜单为每个模板选择一种协议。应用生成各自不同的 HID 描述符、报告和必要的初始化响应，键盘通过独立 HID 设备同时输出。

| 协议 | VID:PID / 报告 | 按键与体感 |
| --- | --- | --- |
| Xbox 360 | `045e:028e` / 15 字节 | 双摇杆、模拟扳机、方向键与功能键；没有体感字段。 |
| NS Pro | `057e:2009` / 49 字节 `0x30` | 12 位摇杆、数字 ZL/ZR、每包三组加速度/角速度；支持 USB 初始化、子命令及校准读取。中间「截图」发送 Capture，Android 映射为 BUTTON_MODE。 |
| PS / DualShock 4 | `054c:05c4` / 64 字节 `0x01` | △○×□、L1/R1、模拟 L2/R2、SHARE/OPTIONS/PS；加速度/角速度、校准特征报告。没有屏幕触摸板或振动反馈。 |
| FPV USB HID 遥控器 | `1209:5459` / 18 字节 | Mode 2，八个无符号 16 位通道；不是 CRSF/SBUS，也不向实体飞行器发送无线控制。 |

「+ 键盘 / 手柄」的选择区随协议变化：Xbox 的错位摇杆、NS 的对应 ABXY 顺序及 ZL/ZR、PS 的对称摇杆和符号键、FPV 的双摇杆加四个辅助通道。编辑画布/悬浮控件使用对应默认名称；用户自定义名称优先。切换协议保留模板的位置、样式和各控件的隐藏设置。

FPV 只显示两个摇杆和 CH5～CH8 四个可选辅助开关，不列出通用 HID 的 B1/B2 等按钮：

| 通道 | 屏幕操作 | 松手行为 |
| --- | --- | --- |
| CH1 横滚 | 右摇杆左右 | 回中 |
| CH2 俯仰 | 右摇杆上下，上为高值 | 回中 |
| CH3 油门 | 左摇杆上下，上为高值 | **保持上下位置** |
| CH4 偏航 | 左摇杆左右 | 回中，不改变油门 |
| CH5～CH8 | 四个独立辅助控件，点按在 0%、50%、100% 间循环 | 保持档位，默认 50% 中档 |

新启动 FPV 时，左摇杆在最底部，CH3=0。再次落指不改变当前油门，拖动从上次值继续；固定和半屏浮动模式都适用。轴独立限幅，横向拨到最边缘不会降低油门。收起、进入编辑、被「仅横屏启用」暂停、重新加载模板或停止时，油门归零、辅助通道回到 50% 中档；重新展开从底部开始。长按摇杆仍可发出独立的摇杆按下事件。Android 通用驱动把 CH3 映射到原生 `AXIS_THROTTLE`，系统初始值即 0，显示范围 0～1。CH1～8 对应 X/Y/THROTTLE/RX/RY/RZ/Z/RUDDER，其余通道在系统测试中显示为 −1～+1。

0.5.4 修复 FPV 右摇杆仍按圆形限幅的问题：左右两个摇杆都按正方形范围独立限制两轴，右摇杆斜向到底时横滚和俯仰可同时达到满值，松手后双轴回中。固定和浮动样式都适用，无需重建或修改模板。

### IMU 检测结果与边界

0.5.3 的「系统输入测试」分为三个独立区域：本机加速度/陀螺仪的计数和实时值；所选协议的写入确认计数（NS 同时显示第三组 IMU 原始值）；系统 `InputDevice` 实際提供的体感接口和回传。写入确认来自已完成 `/dev/uhid` 写入后的 ADB/Binder 回复，不能据此认为系统或接收软件读到了体感。接口缺失时显示明确状态，不用本机读数代替系统回传。

2026-10-08 HBN-AL00 手机实测：两种本机传感器均有持续样本，非零 NS IMU 报告持续写入成功；已绑定 Nintendo 驱动，但该驱动仅建立按键/摇杆事件节点，未提供体感节点。用临时 uinput 测试注册传感器时，系统将其识别成独立设备，未合并到 NS 手柄；临时设备已经移除，此方案没有加入应用。

应用自己注册本机加速度计和陀螺仪，约 200 Hz 采样，按当前横竖屏方向转换坐标后打包。优先使用校准陀螺仪，缺失时尝试未校准接口并减去偏置；超过 250 ms 的旧样本归零。缺失传感器的通道发送零，不伪造读数。齿轮 →「传感器检测」列出 Android 实际暴露的传感器。

2026-10-07 实测 DBR-W10 / 鸿蒙 4.2.0.247：加速度计可采样，Android 传感器列表没有陀螺仪（TYPE_GYROSCOPE=4）或未校准陀螺仪（16），系统也未声明 gyroscope feature。传感器隐私开关未禁用采样；这不是应用缺少运行时授权。官方 [MatePad 11 2023 规格](https://consumer.huawei.com/ae-en/tablets/matepad-11-2023/specs/) 的传感器列表同样不列陀螺仪。

本机 Sony 驱动可建立输入设备传感器节点，PS 模式的实际加速度已由独立测试页通过 `InputDevice.getSensorManager()` 收回。本机 Nintendo 驱动只暴露按键与轴，**没有体感输入节点**：NS 报告包含加速度样本，但此固件不会把它们转为 Android 输入设备传感器。是否被下游串流软件/模拟器转发或读取，仍取决于系统驱动和下游支持；未逐应用验证。

## 键盘、名称与控件选择

- 编辑 →「+ 键盘 / 手柄」显示完整键盘布局，可一次多选新增，选中键高亮，点击「应用选择」提交。最多 32 个键盘控件；修饰键支持和其他键多指组合。
- 所有键盘控件尺寸统一调整，横竖屏各保存一套尺寸。拖动位置仍各自独立。
- 上方手柄/遥控器区：**点亮表示保留；再次点击取消高亮表示删除；再点亮恢复**。恢复保留原有位置、尺寸和名称。点击「取消」不会修改草稿。
- 点选画布控件也可删除；键盘删除后可重新添加。ABXY 组合可按单键隐藏，隐藏触区不发送输入；浮动摇杆删除后不会留下拦截触摸的半屏窗口。
- 「编辑按键名称」可设置普通名称，勾选「点按切换高亮」后可另设高亮名称。再次点按取消高亮。**高亮仅改变显示，不会持续按住游戏按键或键盘键**；实际按下和松开仍跟随手指。高亮会话状态不写入模板。
- 顶部「仅横屏启用」勾选后，竖屏隐藏控件并暂停输入/IMU，恢复横屏后重新显示；已收起的手柄保持收起。

## 收起与展开

运行时没有 TX / 编辑 / 收起 / 关闭工具栏。

- 点击预先编辑的收起区域，会释放全部按键并隐藏悬浮控件；FPV 油门归零、辅助开关回中。该区域在左右浮动摇杆的手势入口中也被明确排除，区域内落指不会启动摇杆或触发 L3/R3。
- 在实测鸿蒙 4.2 设备上，使用**鸿蒙系统智慧多窗悬浮球**，由 SystemUI 负责贴边；点击气泡恢复手柄。没有绘制仿制气泡。
- 实现为独立的系统悬浮窗任务，使用华为窗口模式 102 和 `Activity.moveTaskToBack()` 进入悬浮球；适配依赖固件的窗口行为。其他厂商/系统未验证。系统不接受悬浮窗时，会提示通过常驻通知「展开」恢复。
- 回到主应用会暂时隐藏悬浮层，便于编辑；通知和主界面都能停止手柄。锁屏或连接断开也会释放并移除虚拟设备。

完全停止应用和 ADB 后端：

```powershell
.\stop.ps1 -Adb 'D:\platform-tools\adb.exe'
```

## 设备与权限

- Xbox 模式设备名称 `Microsoft X-Box 360 Pad`，VID/PID `045e:028e`，GAMEPAD / JOYSTICK 来源；其他协议身份见下表。
- 支持 ABXY、LB/RB、View/Menu、Guide、L3/R3、八向方向键、双摇杆和双模拟扳机。
- 不依赖无障碍服务。可用无线调试的设备无需 Root；Shizuku 也支持已有 Root。不是 Windows XInput API，不连接 Xbox 主机，没有振动反馈。
- Shizuku 方式不监听网络端口；用户授权后通过 Binder 连接专属 UserService，后台核对调用 UID、会话和报告长度。停止、权限失效或超时会释放虚拟输入设备。
- 兼容 ADB 后端仅监听 `127.0.0.1:37684`，不监听局域网。INTERNET 权限仅用于这条设备本地连接。
- ADB 激活使用随机 256 位密钥及双方独立角色的 HMAC-SHA256 随机挑战。密钥通过受 DUMP 权限保护的接收器交给应用；shell 临时密钥文件读后删除。运行 `activate.cmd` 会自动切换到 ADB 方式。
- 每次事件发送完整状态；数字边沿排队，轴移动可合并。Xbox/FPV 闲置时约 100 ms 一次心跳；NS/PS 约 15 ms 发送体感报告，连接超过约 1 秒无数据则移除设备。这不是实测延迟指标。
- 控件窗口 alpha 保持 1，透明度仅作用于图形绘制，避免鸿蒙丢弃低窗口不透明度的触摸。
- 最低 API 26、target API 34。系统悬浮球已在 DBR-W10 鸿蒙 4.2 验证；其他型号/固件需自行验证。

## 故障定位

- `/dev/uhid` 报 `EACCES`：该固件不允许 shell 创建输入设备；本程序报告失败，不会降级为触屏映射。
- 无设备：先在设置中「检测输入服务」。Shizuku 方式检查其运行和授权状态；ADB 方式可查看 `/data/local/tmp/touchxbox-bridge.log` 并重新激活。已连接电脑时也可用 `adb shell dumpsys input` 检查实际设备。
- 键盘按键：保存模板并启动悬浮层后，在「系统输入测试」查看 `KEYCODE_W` 等系统事件。编辑和预览只调整布局，不发送输入。2026-10-08 HBN-AL00 实测独立 `TouchXbox Keyboard`，`SOURCE_KEYBOARD=0x101`、字母键盘类型 2；NS 模式下 W、空格、F4 均收到 DOWN/UP。
- NS 体感：同一手机的加速度和陀螺仪采集均持续更新，但固件没有给 NS 虚拟手柄提供输入设备传感器接口。测试页的系统 IMU 为 0 不能当作本机采集失败；也不能据本机采集正常就宣称接收软件已取得体感。
- 个别应用忽略虚拟设备：系统识别不保证所有应用接受，本项目不逐游戏适配。
